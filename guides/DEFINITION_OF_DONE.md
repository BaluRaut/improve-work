# Definition of Done

Use this as a shared baseline and adapt it to the team's engineering standards. Not every item applies to every change; mark it not applicable where appropriate.

## Story / task Done

- [ ] Acceptance criteria are implemented and verified.
- [ ] Code has been reviewed and meets repository standards.
- [ ] Unit and relevant integration / contract tests pass.
- [ ] Relevant end-to-end, regression, accessibility and localization checks pass or have an agreed follow-up.
- [ ] API contracts, schemas and backward compatibility are respected.
- [ ] Security, privacy and authorization checks are completed where relevant.
- [ ] Logging, metrics, traces, analytics and alerts are updated where relevant.
- [ ] Feature flags, configuration and secrets are handled safely.
- [ ] Documentation, runbooks and support guidance are updated where relevant.
- [ ] No known critical or high-severity defect remains unresolved without explicit acceptance.
- [ ] Work item links, status and evidence are up to date.

## Feature / release Done

- [ ] All required work items are complete or explicitly descoped with approval.
- [ ] Product and QA have validated the agreed feature-level acceptance criteria.
- [ ] Required migrations and infrastructure changes are applied safely.
- [ ] Rollout and rollback / kill-switch procedures are verified as applicable.
- [ ] Support, operations and impacted teams have received required communication.
- [ ] Production monitoring and dashboards are working.
- [ ] Release notes and user-facing documentation are updated where relevant.
- [ ] Feature flag cleanup and technical-debt follow-ups are recorded.
- [ ] Success and guardrail metrics have an owner and review date.
- [ ] Actual outcomes are recorded in the RFC or outcome review, including follow-up actions.

A deployment alone does not make a feature Done when the agreed user outcome or operational checks have not been verified.
